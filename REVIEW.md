# REVIEW.md

## Defects found in the starter implementation

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes()` (lines 33–37) | The shift start is constructed on the punch-in calendar date, which produces incorrect lateness calculations for overnight shifts. | Test an overnight shift, such as 22:00–06:00, with a punch-in after midnight. | Resolve the correct shift date and calculate lateness using the scheduled start in IST. |
| 2 | `compute_work_hours()` (lines 40–41) | Python's built-in `round()` uses ties-to-even rounding, whereas the contract requires half-up rounding to two decimal places. | Test a duration whose calculated hours fall exactly on a two-decimal rounding midpoint. | Use explicit half-up rounding to two decimal places after truncating timestamps to whole seconds. |
| 3 | `compute_overtime()` (lines 44–47) | The shift end is always constructed on `date_str`, which mishandles overnight shifts. The required minimum 30-minute overtime threshold is also missing. | Test overnight shifts and punch-outs 29 and 30 minutes after the scheduled shift end. | Resolve the correct shift-end date and apply the 30-minute threshold, counting only whole elapsed minutes. |
| 4 | `EmployeeIn` shift validation (lines 53–60) | Shift times and `joined_on` are plain strings without sufficient format and semantic validation. Equal shift start and end times are not rejected. | Submit malformed times, an invalid date, or identical shift start and end times. | Validate the required formats and reject invalid dates, times, and equal shift times. |
| 5 | `PunchInIn.status` (lines 63–66) | The punch-in status is an unrestricted string, allowing values that are not valid for punch-in. | Submit `ABSENT`, `LEAVE`, or an unknown status to the punch-in endpoint. | Restrict the status to `PRESENT`, `WFH`, and `ON_DUTY`, as required by the contract. |
| 6 | `health()` (lines 72–74) | The endpoint always reports success without checking MongoDB connectivity. | Make MongoDB unavailable and request `/health`. | Ping MongoDB and return HTTP 503 when the database is unavailable. |
| 7 | `create_employee()` (lines 77–85) | Checking for a duplicate employee code before insertion is not atomic. Concurrent requests can both pass the check. | Send concurrent employee-creation requests using the same `emp_code`. | Enforce a unique index on `emp_code` and handle duplicate-key errors with HTTP 409. |
| 8 | `create_employee()` response (lines 81–85) | `created_at` is returned as a datetime rather than the epoch-millisecond integer required by the API contract. | Create an employee and inspect the JSON type and value of `created_at`. | Serialize `created_at` as the required epoch-millisecond integer. |
| 9 | `list_employees()` (line 93) | `skip = page * page_size` skips the first page of results. | Request page 1 and check whether the first `page_size` employees are returned. | Calculate the offset as `(page - 1) * page_size`. |
| 10 | `list_employees()` (lines 90–96) | The total count ignores the department filter applied to the item query. | Request employees for a specific department and compare `total` with the number matching that department. | Use the same filter for the count and item queries. |
| 11 | `list_employees()` (lines 88–96) | Pagination inputs are not validated against the required bounds. | Request page 0, a negative page size, or a page size greater than 100. | Validate pagination inputs and enforce the required defaults and maximum page size. |
| 12 | `punch_in()` (lines 101–114) | The employee lookup result is not checked before accessing `emp["shift_start"]`, so an unknown employee can cause a server error. | Punch in using an unknown `emp_code`. | Return HTTP 404 when the employee does not exist. |
| 13 | `punch_in()` (lines 102–103) | Epoch timestamps and generated timestamps are interpreted using naive local datetimes instead of consistently applying IST. | Submit an epoch-millisecond timestamp and verify the stored attendance date and time against IST. | Convert timestamps explicitly to IST and derive the attendance date from the IST timestamp. |
| 14 | `punch_in()` (lines 104–118) | The existing-record check and subsequent insert are separate operations, allowing concurrent requests to create duplicate attendance records. | Send simultaneous punch-in requests for the same employee and date. | Enforce a unique compound index on `emp_code` and `date`, and handle duplicate-key errors with HTTP 409. |
| 15 | `list_attendance()` (lines 144–150) | All matching attendance records are loaded into Python and sorted there before pagination, which is inefficient for large collections. | Run a listing query against a large dataset and inspect the query execution and memory usage. | Perform filtering, counting, sorting, skipping, and limiting in MongoDB. |
| 16 | `list_attendance()` (lines 124–150) | Pagination parameters are not validated against the required bounds, and invalid status values are not rejected by request validation. | Request an invalid page size or `/attendance?status=INVALID`. | Validate pagination parameters and restrict status to the contract's allowed values. |
| 17 | `list_attendance()` date filters (lines 124–141) | The date parameters are unrestricted strings and are not validated against the exact `YYYY-MM-DD` format. | Submit a malformed date or an alternative ISO representation that does not match the required format. | Validate the exact date format and reject invalid calendar dates. |
| 18 | Lines 153–161 | The starter explicitly leaves punch-out, attendance regularization, monthly employee analytics, department summary, late leaderboard, department trend, and explain functionality unimplemented. | Call each required endpoint in the starter application. | Implement the missing endpoints, including their validation, calculations, aggregation pipelines, and query-plan functionality. |

## Areas reviewed and determined not to be defects

| Area | Why it was not considered a defect |
|---|---|
| Environment configuration (lines 20–23) | The starter reads `MONGO_URI` and `MONGO_DB` from environment variables and loads a local `.env` file for convenience. The local MongoDB default is not itself a defect. |
| Employee department filter (lines 90–92) | The department filter is correctly applied to the employee item query. The defect is that the total count does not use the same filter. |
| Attendance date-range query construction (lines 136–141) | Using `$gte` and `$lte` provides inclusive date boundaries for consistently formatted ISO date strings. The missing input validation is a separate defect. |
| Punch-in duplicate pre-check (lines 104–105) | Checking for an existing record is useful for returning a clear conflict response. The defect is relying on this check alone without an atomic uniqueness guarantee. |
| Work-hours elapsed-time formula (line 41) | Subtracting timestamps and converting elapsed seconds to hours is appropriate. The defect is the rounding policy, not the elapsed-time formula. |
